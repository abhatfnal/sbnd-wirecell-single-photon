# Source semantics of `shw_sp_n_20br1_showers` (the frozen final cut `== 1`)

Date: 2026-11-11. Branch `analysis/ncdelta-remaining-frozen-stage-audit-20261111`. Audit only. SOURCE: `clus/src/NeutrinoTaggerSinglePhoton.cxx` at fg1 `4b6853d4` (`singlephoton_tagger` lines 2268-2520, `bad_reconstruction_sp` lines 186-470); extends `WIRECELL_SINGLE_PHOTON_SHOWER_COUNT_SEMANTICS.md` sections 1-3. MEASURED = official Gen2 NC-Delta (`tables/remaining_stage_audit/n20br1_*.csv`).

## 1. Exact definition
* **Shower set.** Only the showers of `map_vertex_to_shower[main_vertex]`: the showers whose **start vertex is the candidate's main vertex** (attached or detached, connection type 1-3); showers elsewhere in the graph, of other candidates, or in far clusters (type 4) are never examined.
* **Typing.** Only electron-typed showers (`pdg == 11` of the start segment) are examined; a shower typed muon / pion / proton is routed to the MIP / proton bookkeeping and **never counted**.
* **`en20`.** `tmp_energy = kine_best` (`kine_charge` if `kine_best == 0`) `> 20 MeV`, strictly.
* **`badreco1 = !bad_reconstruction_sp(shower)`**, a shower is "good" for br1 if none of three sub-checks flags it as a mis-reconstructed long muon-like track: **br1_1** (stem): `start_type == 1`, vertex degree 1, `E < 120 MeV`, `<= 3` segments, no shower-topology / trajectory flag and stem `> 10 cm`; or stem `> 80 cm`; **br1_2** (longest muon-like track inside the shower, extended through `find_cont_muon_segment_nue`): the effective length exceeds an energy-dependent threshold (38-50 cm at `E < 200 MeV` rising to 55-75 cm above 1.5 GeV, depending on the number of connected vertices) or exceeds 0.75 of the total shower length and 35 cm; **br1_3** (straight track near the far end of the start segment): a long straight continuation (> 165-170 degrees) `> 10 cm`. **No attachment requirement** enters br1 (unlike `br2`, which is evaluated only if the start segment is directly attached to the main vertex).
* **Counter.** `num_20br1_shws += en20 && badreco1`; `shw_sp_n_20br1_showers = num_20br1_shws` (line 2520), so **`n_20br1 <= n_20mev`** and both count the same electron-typed main-vertex shower set; `n_br1_showers` counts `badreco1` without the energy requirement.
* **Relation to `shw_sp_filled`.** The max shower (the only one for which `shw_sp_*` are filled, `shw_sp_filled = 1`) must satisfy `en20 && badreco1` (the "good" pick requires also br3 and br4, the "ok" fallback only `en20 && badreco1`): **`shw_sp_filled == 1` implies `n_20br1 >= 1`.** Candidates with `n_20br1 == 0` have `shw_sp_filled == 0` and are not BDT-evaluable.
* **Consequence for the frozen cut.** After the BDT stages every surviving candidate is filled, so `n_20br1 >= 1`: **MEASURED, of the 1,313 events entering the `n_20br1` stage none has `n_20br1 == 0`** (1,148 have 1 / 1 and 5 have (2, 1) shower counts and pass; 160 have `n_20br1 >= 2` and fail; `n20br1_n20mev_vs_n20br1.csv`). The cut `== 1` is therefore operationally the **multiplicity veto `n_20br1 < 2`**: it removes candidates with two or more good, > 20 MeV, electron-typed showers at the main vertex.
* **Not a photon count.** It counts reconstructed shower objects of one set, not truth photons: a single photon that the pattern recognition splits into two > 20 MeV showers at the vertex counts 2 (section 15 of the combined report: 126 of the 160 removed events).
* `shw_sp_n_20br1_showers` is also an input of the numu, ncpi0 and nue BDTs (`FROZEN_BDT_DEPENDENCY_GRAPH.md`); the event-level cut uses the `any` logic over the candidates that reached the stage.
